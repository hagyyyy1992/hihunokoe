# E2Eテスト オンデマンド実行ガイド

E2Eテストは通常のCIパイプラインでは実行されませんが、必要に応じて手動で実行できます。

## 実行方法

### 1. PRコメントで実行

PRにコメントすることでE2Eテストを実行できます。

#### 基本的な使い方

```bash
/e2e
```

すべてのE2Eテストを実行します。

#### 特定のテストパターンを指定

```bash
/e2e e2e/auth/**
```

認証関連のテストのみを実行します。

```bash
/e2e e2e/posts/create-post.spec.ts
```

特定のテストファイルのみを実行します。

#### 閾値を指定

```bash
/e2e --threshold=90
```

パス率の閾値を90%に設定して実行します。

```bash
/e2e e2e/auth/** --threshold=95
```

認証テストを95%の閾値で実行します。

### 2. GitHub Actions UI から実行

1. GitHubリポジトリの「Actions」タブを開く
2. 左側のワークフロー一覧から「E2E Tests (On-Demand)」を選択
3. 「Run workflow」ボタンをクリック
4. 必要に応じてパラメータを入力：
   - **Test pattern**: 実行するテストパターン（例: `e2e/auth/**`）
   - **Threshold**: パス率の閾値（0-100の数値）
5. 「Run workflow」をクリック

## 権限

- PRコメントでの実行には、リポジトリへの**Write権限**が必要です
- 権限がない場合は、エラーメッセージが表示されます

## 実行結果

### PRコメントの場合

1. コマンドを実行すると、🚀リアクションが付きます
2. テスト開始時にコメントで通知されます
3. テスト完了後、結果がコメントで報告されます

### 結果の例

```
✅ E2E tests passed!

- Test pattern: e2e/auth/**
- Pass threshold: 90%
- Status: All tests passed successfully

### 📊 Test Summary
- Total tests: 45
- Passed: 45
- Failed: 0
- Pass rate: 100.0%
```

## テストパターンの例

- `e2e/**` - すべてのE2Eテスト
- `e2e/auth/**` - 認証関連のテスト
- `e2e/posts/**` - 投稿関連のテスト
- `e2e/auth/login.spec.ts` - ログインテストのみ

## トラブルシューティング

### テストが実行されない

1. コメントに`/e2e`が正しく含まれているか確認
2. リポジトリへのWrite権限があるか確認
3. PRのステータスを確認（クローズされていないか）

### テストが失敗する

1. ワークフローの実行ログを確認
2. アップロードされたテスト結果のアーティファクトを確認
3. ローカルで同じテストを実行して再現性を確認

## 注意事項

- E2Eテストは実行に時間がかかるため、必要な時のみ実行してください
- 複数の実行が同時に行われると、リソースの競合が発生する可能性があります
- テスト結果のアーティファクトは30日間保存されます
