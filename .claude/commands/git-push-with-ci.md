---
name: git-push-with-ci
description: コード品質チェック後、[ci]タグ付きでcommit & push（CI実行あり）
---

プロジェクトのコード品質を確認してから、git add、commit、pushを一括で実行します。コミットメッセージに自動的に `[ci]` タグを追加し、GitHub ActionsのCIを実行させます。

## 実行フロー

1. **事前チェック**: コードの品質を確認
2. **エラー修正**: 問題があれば修正を実施
3. **再チェック**: 修正後に再度確認
4. **変更の追加**: git add -A で全ての変更をステージング
5. **コミット作成**: 適切なコミットメッセージに `[ci]` を追加してコミット
6. **Push実行**: リモートリポジトリへpush（CIが自動実行される）

## チェック項目

以下のコマンドを順次実行し、全てが成功することを確認します：

```bash
# 1. フォーマット実行（自動修正）
npm run format

# 2. Lint実行（エラー検出）
npm run lint

# 3. テスト実行
npm test

# 4. TypeScript型チェック
npx tsc --noEmit
```

## エラー時の対応

- **フォーマットエラー**: 自動修正された差分をコミット
- **Lintエラー**: 指摘された箇所を修正
- **テスト失敗**: 失敗したテストを確認し、コードまたはテストを修正
- **型エラー**: TypeScriptの型エラーを修正

## 実行コマンド

```bash
# 1. 全てのチェックを連続実行
npm run format && npm run lint && npm test && npx tsc --noEmit

# 2. 成功した場合のみ、変更をステージング
git add -A

# 3. コミットメッセージを生成してコミット（[ci]タグを自動追加）
# 形式: prefix: 〇〇なため、△△を追加/修正/削除 [ci]
git commit -m "コミットメッセージ [ci]"

# 4. リモートリポジトリへpush
git push
```

## コミットメッセージの生成

コミットメッセージは以下の手順で生成します：

1. **変更内容の確認**: `git diff --cached` で変更内容を確認
2. **prefix選択**: 変更の種類に応じて適切なprefixを選択
   - feat: 新機能追加
   - fix: バグ修正
   - docs: ドキュメント変更
   - style: コードスタイル変更
   - refactor: リファクタリング
   - test: テスト追加・修正
   - chore: ビルド・ツール関連
3. **理由と内容**: 「〇〇なため、△△を追加/修正/削除」形式で記述
4. **[ci]タグ追加**: メッセージの最後に必ず ` [ci]` を追加

## 通常のgit-pushとの違い

| 項目               | git-push                     | git-push-with-ci           |
| ------------------ | ---------------------------- | -------------------------- |
| コミットメッセージ | 通常のメッセージ             | 自動的に `[ci]` タグ付き   |
| CI実行             | PRでは実行されない可能性あり | 必ず実行される             |
| 用途               | 通常の開発時                 | CI確認が必要な重要な変更時 |

## 注意事項

- **CI実行**: `[ci]` タグにより、PRでも必ずCIが実行される
- **実行時間**: CIが実行されるため、通常のpushより時間がかかる
- **依存関係**: package-lock.jsonが変更された場合は必ずコミット
- **mainブランチ**: mainへのマージ時は `[ci]` タグ不要（常に実行される）

## レポート内容

実行結果として以下を報告：

- 各チェックの成功/失敗状態
- 修正が必要な項目の詳細
- git add/commit/pushの実行状態
- 生成したコミットメッセージの内容（[ci]タグ付き）
- CI実行のトリガー状態
- 次のアクションの提案

## 使用例

```bash
# 通常の使用（コミットメッセージは自動生成、[ci]タグ付き）
claude code git-push-with-ci

# コミットメッセージを指定して使用（[ci]タグは自動追加）
claude code git-push-with-ci "fix: ログイン機能のバグを修正するため、認証ロジックを修正"
# → 実際のコミット: "fix: ログイン機能のバグを修正するため、認証ロジックを修正 [ci]"
```

## 使い分けガイド

- **git-push**: 日常的な開発、小さな変更、ドキュメント修正など
- **git-push-with-ci**: 機能追加、バグ修正、リファクタリングなどCI確認が必要な変更
