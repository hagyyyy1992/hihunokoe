name: git-push
description: コード品質チェック後にadd、commit、pushを一括実行
---

プロジェクトのコード品質を確認してから、git add、commit、pushを一括で実行します。CLAUDE.mdの開発原則に従い、全てのチェックが成功した場合のみ実行します。

## 実行フロー

1. **事前チェック**: コードの品質を確認
2. **エラー修正**: 問題があれば修正を実施
3. **再チェック**: 修正後に再度確認
4. **変更の追加**: git add -A で全ての変更をステージング
5. **コミット作成**: 適切なコミットメッセージでコミット
6. **Push実行**: リモートリポジトリへpush

## チェック項目

以下のコマンドを順次実行し、全てが成功することを確認します：

```bash
# 1. フォーマット実行（自動修正）
npm run format

# 2. Lint実行（エラー検出）
npm run lint

# 3. テスト実行
npm test

# 4. TypeScript型チェック
npx tsc --noEmit
```

## エラー時の対応

- **フォーマットエラー**: 自動修正された差分をコミット
- **Lintエラー**: 指摘された箇所を修正
- **テスト失敗**: 失敗したテストを確認し、コードまたはテストを修正
- **型エラー**: TypeScriptの型エラーを修正

## 実行コマンド

```bash
# 1. 全てのチェックを連続実行
npm run format && npm run lint && npm test && npx tsc --noEmit

# 2. 成功した場合のみ、変更をステージング
git add -A

# 3. コミットメッセージを生成してコミット
# 形式: prefix: 〇〇なため、△△を追加/修正/削除
git commit -m "コミットメッセージ"

# 4. リモートリポジトリへpush
git push
```

## コミットメッセージの生成

コミットメッセージは以下の手順で生成します：

1. **変更内容の確認**: `git diff --cached` で変更内容を確認
2. **prefix選択**: 変更の種類に応じて適切なprefixを選択
   - feat: 新機能追加
   - fix: バグ修正
   - docs: ドキュメント変更
   - style: コードスタイル変更
   - refactor: リファクタリング
   - test: テスト追加・修正
   - chore: ビルド・ツール関連
3. **理由と内容**: 「〇〇なため、△△を追加/修正/削除」形式で記述

## 注意事項

- **必須実行**: 変更が1行でも複数ファイルでも必ず実行
- **CI/CD連携**: PR内に`[ci]`タグを含むコミットがある場合、CIが実行される
- **依存関係**: package-lock.jsonが変更された場合は必ずコミット
- **例外なし**: 「緊急」「小さな変更」でも必ずチェックを実行

## レポート内容

実行結果として以下を報告：

- 各チェックの成功/失敗状態
- 修正が必要な項目の詳細
- git add/commit/pushの実行状態
- 生成したコミットメッセージの内容
- 次のアクションの提案

## 使用例

```bash
# 通常の使用（コミットメッセージは自動生成）
claude code git-push

# コミットメッセージを指定して使用
claude code git-push "fix: ログイン機能のバグを修正するため、認証ロジックを修正"
```
