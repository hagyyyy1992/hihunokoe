# バグ修正プロンプトテンプレート

## 概要

Usakaプロジェクトでバグ修正を行う際の体系的なアプローチです。TDDの原則に従い、まずバグを再現するテストを作成します。

## プロンプトテンプレート

```
以下のバグを修正してください：

【バグの概要】
[1行でバグを説明]

【症状】
- 現象: [具体的な症状]
- エラーメッセージ: [あれば記載]
- 発生頻度: [常に/時々/特定条件下]

【再現手順】
1. [手順1]
2. [手順2]
3. [手順3]

【期待される動作】
[正しい動作の説明]

【実際の動作】
[現在の誤った動作]

【環境情報】
- ブラウザ: [Chrome/Firefox/Safari等]
- OS: [Windows/Mac/Linux]
- Node.js: [バージョン]
- 発生箇所: [URL/画面名]

【影響範囲】
- 影響を受ける機能: [機能名]
- 影響を受けるユーザー: [全員/特定条件のユーザー]
- 重要度: [Critical/High/Medium/Low]

【修正方針】
1. まずバグを再現するテストを作成
2. テストが失敗することを確認
3. 最小限の修正でテストをパス
4. リファクタリング（必要に応じて）
5. 回帰テストの実行
```

## 調査・修正チェックリスト

### 1. 問題の理解フェーズ

- [ ] バグを確実に再現できる
- [ ] エラーログを収集・分析
- [ ] 影響範囲を特定
- [ ] 関連するコードを特定

### 2. 根本原因分析フェーズ

- [ ] バグの根本原因を特定
- [ ] なぜバグが発生したか理解
- [ ] 既存のテストでカバーされていない理由を分析
- [ ] 類似のバグが他にないか確認

### 3. テスト作成フェーズ（TDD）

- [ ] **ステップ1**: バグを再現するテストを作成
- [ ] **ステップ2**: テストが失敗することを確認
- [ ] **ステップ3**: テストをコミット（`test: バグ再現テストを追加`）

### 4. 修正実装フェーズ

- [ ] **ステップ4**: 最小限の修正を実装
- [ ] **ステップ5**: テストが通ることを確認
- [ ] **ステップ6**: 他のテストも通ることを確認
- [ ] **ステップ7**: 修正をコミット（`fix: [バグの説明]`）

### 5. 品質保証フェーズ

```bash
# 必須チェック
npm run format && npm run lint && npm test && npx tsc --noEmit
```

- [ ] 全ユニットテスト通過
- [ ] E2Eテストで回帰なし
- [ ] 手動での動作確認
- [ ] パフォーマンスへの影響なし

### 6. 予防策フェーズ

- [ ] 追加のテストケースを検討
- [ ] コードレビューで見逃した理由を分析
- [ ] ドキュメントの更新（必要に応じて）
- [ ] チームへの共有

## 具体例

### ログインエラーの修正

```
以下のバグを修正してください：

【バグの概要】
特定の条件下でログインが失敗し、エラーメッセージが表示されない

【症状】
- 現象: ログインボタンクリック後、画面が更新されるがエラーメッセージなし
- エラーメッセージ: コンソールに "TypeError: Cannot read property 'message' of undefined"
- 発生頻度: メールアドレスに特殊文字が含まれる場合

【再現手順】
1. /auth/login にアクセス
2. メールアドレスに "test+1@example.com" を入力
3. 正しいパスワードを入力
4. ログインボタンをクリック

【期待される動作】
正常にログインし、ダッシュボードへリダイレクト

【実際の動作】
ログインページに留まり、エラーメッセージも成功メッセージも表示されない

【環境情報】
- ブラウザ: Chrome 120
- OS: macOS 14.2
- Node.js: 20.10.0
- 発生箇所: /auth/login

【影響範囲】
- 影響を受ける機能: ログイン機能
- 影響を受けるユーザー: メールアドレスに"+"を含むユーザー
- 重要度: High

【修正方針】
1. __tests__/api/auth/login.test.ts に特殊文字を含むメールのテストを追加
2. テストが失敗することを確認してコミット
3. メールバリデーションロジックを修正
4. エラーハンドリングを改善
5. 全テストが通ることを確認
```

## デバッグのヒント

### コンソールログの活用

```typescript
// 一時的なデバッグログ（修正後は削除）
console.log('DEBUG: Current state:', { user, email, error })
```

### ブレークポイントの設定

```typescript
// Chrome DevToolsでブレークポイントを設定
debugger // 修正後は削除
```

### エラーの詳細情報

```typescript
try {
  // 処理
} catch (error) {
  console.error('Detailed error:', {
    message: error.message,
    stack: error.stack,
    context: {
      /* 関連情報 */
    },
  })
}
```

## 注意事項

1. **テストファースト**: 必ずバグを再現するテストから始める
2. **最小限の修正**: 副作用を避けるため必要最小限の変更
3. **回帰テスト**: 他の機能が壊れていないことを確認
4. **根本原因**: 症状だけでなく原因を解決
