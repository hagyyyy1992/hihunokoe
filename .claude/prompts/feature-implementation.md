# 機能実装プロンプトテンプレート

## 概要

Usakaプロジェクトに新機能を実装する際のTDDベースの標準的なアプローチです。

## プロンプトテンプレート

```
以下の機能をTDD（テスト駆動開発）で実装してください：

【機能名】
[具体的な機能名を記入]

【ユーザーストーリー】
- As a [ユーザータイプ]
- I want to [実現したいこと]
- So that [価値・目的]

【受け入れ条件】
1. [条件1]
2. [条件2]
3. [条件3]

【技術要件】
- API: [必要なエンドポイント]
- DB: [スキーマ変更の有無]
- UI: [画面・コンポーネント]
- 認証: [権限要件]

【実装手順】
1. まずテストを作成（失敗することを確認）
2. テストが正しいことを確認してコミット
3. 実装を進めてテストをパス
4. リファクタリング
5. 統合テスト・E2Eテストを追加

【考慮事項】
- セキュリティ: [SQLインジェクション、XSS対策など]
- パフォーマンス: [N+1問題、キャッシュなど]
- エラーハンドリング: [統一されたエラーレスポンス]
- アクセシビリティ: [WCAG 2.1 AA準拠]
```

## 実装チェックリスト

### 1. 要件分析フェーズ

- [ ] ユーザーストーリーを明確化
- [ ] 技術的な制約を洗い出し
- [ ] 既存機能への影響を評価
- [ ] データベース設計への影響を確認

### 2. 設計フェーズ

- [ ] API設計（RESTful、エラーレスポンス）
- [ ] データベーススキーマ設計
- [ ] UI/UXワイヤーフレーム
- [ ] セキュリティ設計

### 3. TDD実装フェーズ

- [ ] **ステップ1**: テストケースを作成
- [ ] **ステップ2**: テストが失敗することを確認
- [ ] **ステップ3**: テストの正しさを検証
- [ ] **ステップ4**: テストのみをコミット
- [ ] **ステップ5**: 最小限の実装でテストをパス
- [ ] **ステップ6**: リファクタリング
- [ ] **ステップ7**: 全テストが通過することを確認

### 4. 品質保証フェーズ

```bash
# 必須チェック
npm run format && npm run lint && npm test && npx tsc --noEmit
```

- [ ] TypeScript型チェック通過
- [ ] ESLint警告なし
- [ ] 単体テストカバレッジ80%以上
- [ ] E2Eテスト作成
- [ ] セキュリティレビュー

### 5. ドキュメント更新

- [ ] API仕様書更新
- [ ] コンポーネント仕様書更新
- [ ] 必要に応じてCLAUDE.md更新
- [ ] READMEへの機能追加

## 具体例

### ユーザープロフィール編集機能の場合

```
以下の機能をTDD（テスト駆動開発）で実装してください：

【機能名】
ユーザープロフィール編集機能

【ユーザーストーリー】
- As a 登録ユーザー
- I want to 自分のプロフィール情報を編集したい
- So that 他のユーザーに正確な情報を共有できる

【受け入れ条件】
1. ログインユーザーのみアクセス可能
2. 名前、肌タイプ、アレルギー情報を編集可能
3. 保存後は即座に反映される
4. バリデーションエラーは分かりやすく表示

【技術要件】
- API: PUT /api/profile/update
- DB: Userテーブルの更新
- UI: /profile ページに編集フォーム
- 認証: ログインユーザーのみ（自分のプロフィールのみ編集可）

【実装手順】
1. __tests__/api/profile/update.test.ts を作成
2. __tests__/components/ProfileEditForm.test.tsx を作成
3. テストが失敗することを確認してコミット
4. APIエンドポイントを実装
5. フロントエンドコンポーネントを実装
6. E2Eテストを追加

【考慮事項】
- セキュリティ: 他ユーザーのプロフィール編集を防ぐ
- パフォーマンス: 不要なフィールドは更新しない
- エラーハンドリング: フィールドごとのバリデーション
- アクセシビリティ: フォームラベル、エラーメッセージの適切な関連付け
```

## 注意事項

1. **TDDを徹底**: 実装前に必ずテストを書く
2. **段階的コミット**: テスト→実装の順でコミット
3. **品質チェック**: プッシュ前に全チェックを実行
4. **ドキュメント**: 実装と同時にドキュメントも更新
