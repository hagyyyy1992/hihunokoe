## Development Philosophy

### Test-Driven Development (TDD)

原則としてテスト駆動開発（TDD）で進める

1. 期待される入出力に基づき、まずテストを作成する
2. 実装コードは書かず、テストのみを用意する
3. テストを実行し、失敗を確認する
4. テストが正しいことを確認できた段階でコミットする
5. その後、テストをパスさせる実装を進める
6. 実装中はテストを変更せず、コードを修正し続ける
7. すべてのテストが通過するまで繰り返す

### 重要な開発原則

1. **コードの品質保証**

   - プッシュ前に必ず `npm run format && npm run lint && npm test && npx tsc --noEmit` を実行
   - エラーがある場合は修正してから再実行

2. **コミットメッセージ**

   - 形式: `prefix: 〇〇なため、△△を追加/修正/削除`
   - 理由を明確に記載し、日本語で記述

3. **インポートパス**

   - 常に絶対パス（`@/`）を使用
   - 相対パス（`../`）は同一ディレクトリ内のみ

4. **エラーハンドリング**

   - API: 統一されたエラーレスポンス構造を使用
   - フロントエンド: Error Boundaryとtry-catchで適切に処理

5. **セキュリティ**
   - 入力値は必ずバリデーション・サニタイズ
   - JWTトークンの適切な検証
   - レート制限の実装

## スラッシュコマンド

### `/create-pr` - 高品質なプルリクエスト自動生成

プロジェクトの開発効率を向上させるため、高品質なプルリクエストを自動生成するコマンドを用意しています。

#### 機能

- ✅ 変更ファイル・コミット履歴の自動分析
- ✅ 適切なprefix（feat/fix/perf等）の自動判定
- ✅ 技術領域（Frontend/Backend/Database等）の自動検出
- ✅ プッシュ前品質チェック実行
- ✅ CI/CDステータス監視と自動修正
- ✅ 構造化されたPR本文の自動生成

#### 使用方法

```bash
# 基本的な使用
/create-pr

# タイトル指定
/create-pr --title "feat: 新機能追加"

# ドラフトPRとして作成
/create-pr --draft

# CI実行をスキップ（緊急時のみ）
/create-pr --no-ci
```

#### 生成されるPR構造

- **Summary**: 変更概要の箇条書き
- **Changes**: 技術的詳細（Features/Fixes/Performance等）
- **Test plan**: 自動生成されたテスト計画
- **Breaking Changes**: 破壊的変更の有無

これにより、一貫性のある高品質なプルリクエストを効率的に作成できます。
