# Development Workflow with Claude Code

## Overview

このドキュメントは、UsakaプロジェクトでClaude Codeを効率的に活用するためのワークフローを定義します。

## Daily Development Flow

### 1. セッション開始時

```bash
# プロジェクトの現状確認
npm run db:status
git status
npm test
```

### 2. 機能開発フロー

1. **要件確認**: `.claude/prompts/feature-implementation.md` を参照
2. **設計検討**: データベース影響、API設計を確認
3. **実装**: 段階的実装（DB → API → Frontend → Tests）
4. **品質チェック**: `npm run format && npm run lint && npm test`
5. **コミット**: 適切なコミットメッセージでコミット

### 3. バグ修正フロー

1. **問題分析**: `.claude/prompts/bug-fix.md` を参照
2. **再現確認**: ローカル環境で再現
3. **修正実装**: 最小限の変更で対応
4. **テスト追加**: 回帰防止のためのテスト
5. **検証**: 修正内容の確認

### 4. コードレビューフロー

1. **自己レビュー**: `.claude/prompts/code-review.md` を参照
2. **品質確認**: セキュリティ、パフォーマンス、設計
3. **ドキュメント更新**: 必要に応じてCLAUDE.md更新
4. **プルリクエスト**: 適切な説明とともに作成

## Claude Code活用のベストプラクティス

### 効率的な対話

- **具体的な指示**: 「〇〇を実装して」より「〇〇の機能を△△の要件で実装して」
- **コンテキスト提供**: 関連するファイルパスや制約を明示
- **段階的アプローチ**: 大きな変更は段階的に実装

### コード品質維持

- **事前チェック**: プッシュ前に必ず品質チェック実行
- **テスト重視**: 新機能には必ずテストを追加
- **ドキュメント同期**: コード変更時はドキュメントも更新

### セキュリティ意識

- **認証・認可**: 常にセキュリティ観点を確認
- **データ検証**: 入力値の適切な検証
- **秘密情報**: ログや出力に秘密情報を含めない

## トラブルシューティング

### よくある問題と対処法

1. **データベース接続エラー**

   ```bash
   npm run db:setup
   npm run db:status
   ```

2. **テスト失敗**

   ```bash
   npm run test:watch  # 個別確認
   npm run db:seed     # テストデータ再生成
   ```

3. **型エラー**
   ```bash
   npx tsc --noEmit    # 型チェック
   npm run lint        # Lint修正
   ```
